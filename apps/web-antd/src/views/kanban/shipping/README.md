## 1. 页面定位

该页面在 Vue Vben Admin 内保留原本地 Demo 的主要视觉风格，并扩展为七个页签，用于同步来货、SKU 渠道目标、国家渠道计划、今日到货分配和自动分配结果的统一操作。

当前页面是安全演算工作区，不代表领星或 WMS 已经执行库存锁定、创建货件、出库或物流下单。页面“锁定”只影响当前工作区后续演算。

## 3. 七个页签

### 3.1 总控看板

展示：

- 国家渠道总计划；
- 累计回货数量及良品数量；
- STA 已发货目标 SKU 数量；
- 总计划完成率及未分配数量；
- 海运发货占比及 70%-80% 会议目标；
- 15 个国家渠道的计划、已发货、剩余、完成率、时效和规则。已发货按 STA 目的国、运输方式和该渠道目标 SKU 交集统计，不包含同货件中的非目标 SKU；包含 `WORKING` 及后续有效状态，排除 `CANCELLED`；美国两个海运渠道展示为“海运-美森快船卡派”和“海运-美森快船快递派”，内部保留历史代码兼容 STA 关联。

总控看板固定使用当天最新数据，不提供统计/演算日期选择器。页面加载、重新演算、保存和导出前都会刷新为本地当天，后端同时以服务器当天覆盖工作区中的历史 `asOfDate`。

### 3.2 今日到货分配

以服务器当天和来货 `receiptDate` 为准筛选今日货件。“同步今日来货并自动分配”先从飞书全量同步来货，再使用完整工作区中的 SKU 渠道计划、STA 已发货占用、锁定行、截止日、箱规和仓库规则重新演算。

该页假设历史分配货件均已发出：历史分配数量继续占用渠道和 SKU 目标，但不混入今日建单批次。后端在历史占用基线上，只将今日分配行重新聚合为 `todayShipmentBatches`，避免重复建设历史货件。

“导出今日建单表”下载仓库专用 XLSX。`今日建单明细` 按 SKU 平铺店铺、SID、目的站、MSKU/FNSKU、数量、箱数估算、来货来源和处理要求；`今日批次汇总` 提供批次排程及发走节点；`今日未分配` 只包含当天货件。同步分配期间禁止导出，避免下载到演算切换中的结果。

看板展示：

- 今日来货条数、去重 SKU 数、良品数量、已分配和未分配数量；
- 今日可创建 STA、可直接交仓和未分配数量；
- 精简的今日建单清单：渠道、运输方式、店铺、目的站、SKU 建单数量、MSKU/FNSKU、总件数、箱数、排程、发走日期及阻断原因；
- 今日未分配 SKU、数量和原因。

页面不重复展示渠道汇总和逐条分配追溯；完整追溯仍在“自动分配结果”页签查看。

### 3.3 来货数据

来货数据不再由页面手工录入或上传文件，唯一入口是“同步来货数据”按钮。按钮调用后端同步接口，从飞书多维表格的指定视图读取并对齐以下 7 个字段：来货日期、供应商、店铺、SPU、SKU、回货数量、良品数量。

同步规则：

- 以飞书记录 ID 生成稳定的 `receiptId`，不按日期、供应商、SPU、SKU 去重；
- 每次同步以远端视图为准替换日期、供应商、店铺、SPU、SKU、回货数量和良品数量；相同 `receiptId` 已维护的箱数、箱型、每箱件数、备注和人工状态继续保留；
- 未变化记录的稳定 ID 保留，因此仍然合法的锁定分配会继续保留；
- 远端删除的来货、SKU 变化或锁定数量超过新良品数量的记录，其失效锁定会由后端清理；
- 页面只展示 6 个源字段，不展示箱型、箱数、状态、备注和操作列。

### 3.4 SKU 渠道计划

SKU 渠道计划不再由页面手工维护或上传文件，唯一入口是“同步 SKU 渠道计划”按钮。按钮从飞书多维表格 `tblD2OyaCb850QU5` 的视图 `vewkFB8koH` 读取 `SPU + SKU + 15 个渠道目标量`，完整替换工作区计划并重新演算。表格只读，宽度固定并支持横向滚动，SPU 和 SKU 两列保持粘性定位。

同步规则：

- 美国、加拿大、英国和德国使用飞书中的最终渠道计划字段；澳洲和阿联酋兼容当前表内实际有值的备用字段；
- 飞书公式结果按表格 0 位小数的显示规则四舍五入；
- 同一 SKU 的多条远端记录按渠道数量求和合并；
- 同一 SKU 对应不同 SPU 时后端拒绝同步，避免错误覆盖；
- 同步使用共享工作区 revision 乐观锁，冲突时刷新页面数据，不覆盖其他用户的新修改。

### 3.5 自动分配结果

自动分配只处理尚未通过 STA 发货的良品。来货记录包含店铺，系统按店铺核对 STA 已发数量，避免其他店铺的历史货件抵扣当前来货；剩余良品才进入锁定、建议分配和未分配处理。每个来货 SKU 必须命中 SKU 渠道计划或明确的 SPU 兜底计划。命中计划后按实际件数分配；只有美国按 `店铺 + SKU + 渠道` 汇总凑整 5 件，其他国家按实际可发数量发货。不同店铺不能合并美国尾数、凑箱或生成同一货件。

页面默认展示“建单批次”，按 `渠道 + 目的站 + 店铺/SID` 聚合，展开后可查看来货店铺、SPU、SKU、MSKU、FNSKU、渠道目标、STA 已占用、本次建单、建单后累计、预计箱数和来货来源。`LLW000194`、`LLW000807` 已确认为 VIDUSSA 商品，系统按原国家直接使用对应的 `VIDUSSA-*` 店铺。其他来货指定店铺后只匹配同店铺 Listing，缺失或歧义时阻断，禁止换到其他店铺；同国家其他店铺存在候选时，阻断明细列出候选店铺并提示修正来货源数据。“来货来源追溯”保留店铺、原分配行、规则提示和锁定操作。

批次区分两个执行层级：系统优先使用当天 FBA 库存快照中的当前 Listing，STA 历史货件只作回补；目标站点只有唯一 MSKU/FNSKU 时为“可创建 STA 计划”。同时通过美国 5 箱、英国店铺级 IEN、加拿大整批和临期复核后才是“可直接交仓”。缺 Listing 或存在多个店铺候选时明确阻断，不自动任选；欧洲 DE/FR 合并渠道存在德国 Listing 时优先德国入仓。仓库日产能用于批次开始/完成排程，开始日不得早于该批次的最晚来源来货日；排程后的发走日超过渠道最早截止日时显示“仓库排程已超期”，不能直接交仓。

美国美森快船卡派、美森快船快递派和空运都在同一店铺的最终建单批次内执行 5 箱一致配置门槛，不同店铺不得合并凑箱。系统先按 SKU 固定目标预留空运；美国目标按 5 件单位向上取整，其他国家保持目标原数量。剩余数量才能分配海运，空运仍有缺口时海运批次不能直接交仓。英国 IEN 不再按件数限制，同一店铺、同一非空运渠道允许合并多个 SKU，但一票货至少 6 箱，不自动拆分 IEN；不足 6 箱或箱数未知时不能直接交仓。英国空运不参与 IEN。加拿大、欧洲、澳洲和中东不执行该英国 IEN 规则，继续执行各自规则。

来货缺少箱规时，后端先参考当前来货中相同 SKU 的可信每箱件数，再使用 STA 相同 SKU、相同运输方式的历史装箱众数；仍没有时，采用同运输方式历史使用次数最多的箱体尺寸做保守体积粗估。预计箱数下方会标明“参考同 SKU”或“参考常用箱规”，悬停可查看具体依据。

操作：

- 按国家渠道筛选；
- 按可直接交仓、可创建 STA 计划或存在阻断筛选；
- 展开批次查看建单 SKU 和来货来源；
- 导出包含建单批次及 SKU 明细的 Excel；
- 重新分配全部未锁定数据；
- 锁定或解锁单条结果。

锁定后，后端重算优先扣除锁定数量，并排除同一“来货 + 渠道”的再次建议分配。解锁后该数量重新参与演算。

### 3.6 渠道配置

该页不再重复总控看板中的已发货、剩余和完成率，也不再开放渠道代码、名称、运输方式与计划量的手工修改。

SKU 渠道计划同步后，后端按 15 个渠道汇总全部 SKU 目标并自动更新渠道计划量。页面只读展示渠道身份和汇总计划量，可维护：

- P0/P1/P2；
- 时效要求；
- 分配规则；
- 是否启用。

渠道代码、名称和运输方式是 STA 匹配及分配算法使用的结构字段，由系统维护，避免误改后使 SKU 计划、STA 统计和锁定记录失效。保存配置后重新演算全部未锁定数据。

### 3.7 规则设置

可维护：

- 美国 SKU 货件凑整单位固定为 5 件，尾数等待后续来货合并；其他国家不凑整；
- 美国建单批次一致装箱核心箱数，默认 5 箱，适用于美森快船卡派、美森快船快递派和空运；
- 美国 SKU 凑箱等待小时数；
- 交仓节点预警天数，默认 2 天；
- 加拿大海运整批释放比例，默认 100%；
- 海运占比目标下限和上限，默认 70%-80%；
- 英国 IEN 最低 6 箱，同一店铺、同一非空运渠道可合并多个 SKU；
- 仓库每日处理能力；
- 主市场完成率门槛；
- 5 箱凑箱统一处理截止日，默认 2026-08-16。

“恢复默认”只恢复规则，不清理来货和 SKU 计划。页面不提供清空整个工作区的操作。

## 4. 页面状态和请求流程

初始化流程：

1. 并行请求 `fetchShippingAllocationMeta()` 和 `fetchShippingWorkspace()`；
2. 从元数据复制默认规则，用于“恢复默认”；
3. 使用工作区内容请求 `simulateShippingAllocation()`；
4. 渲染 KPI、渠道进度和分配结果。

保存类操作采用：

```text
修改本地工作区 -> 调用 simulate -> 携带 revision 调用 PUT workspace -> 更新 revision/updatedAt
```

先演算、后保存可以保证无效渠道、重复来货编号、悬空锁定或锁定超量不会写入工作区。

页面不使用 `localStorage` 保存业务数据。所有授权用户读取同一个共享工作区，状态由后端保存到 MySQL 的 `shipping_allocation_workspaces`，刷新、重新登录或更换电脑后仍然保留。保存使用 `revision` 乐观锁；服务端返回 409 时页面重新加载最新工作区，避免覆盖他人的修改。

自动分配先要求 SKU 或 SPU 渠道计划，再按市场层级 P0/P1/P2 为逐 SKU 固定空运目标预留数量，预留后的剩余库存才进入非空运渠道。空运目标保持独立，不参与海运或卡航的动态拆分；有效空运目标尚有缺口时，对应 SKU 的海运批次显示“等待空运目标”，不能直接交仓。SKU 的国家非空运合计和国家渠道总计划是硬约束；美国卡派目标大于 0 且时间充裕时，允许把该 SKU 的快递派基准量补入卡派，直到卡派总计划用满。卡派不可发或总计划已满后，才由同国家快递派/卡航承接。所有渠道按实际可分配件数分配；美国再按店铺、SKU 和渠道执行 5 件凑整，其他国家不凑整。渠道截止日按演算日期与来货日期的较晚值判断：全部区域过期时跳过渠道；部分区域过期且缺少区域数量时也不自动分配该渠道，而把该渠道剩余目标转入同国下一个完全可发渠道。英国非空运优先集中到同一渠道；海运提示同时显示周六收货截止日、下周三发走日期和渠道最晚发货时间。澳洲、中东的空运和非空运都要等重新计算后的主市场完成率严格超过门槛后才释放。

## 5. API 函数映射

| 前端函数 | 方法与路径 | 用途 |
| --- | --- | --- |
| `fetchShippingAllocationMeta` | `GET /kanban/shipping/meta` | 规则版本和默认规则 |
| `simulateShippingAllocation` | `POST /kanban/shipping/simulate` | 执行纯演算 |
| `calculateShippingCartons` | `POST /kanban/shipping/cartons/calculate` | 计算四种箱型的单箱件数和总箱数 |
| `fetchShippingWorkspace` | `GET /kanban/shipping/workspace` | 读取当前用户工作区 |
| `saveShippingWorkspace` | `PUT /kanban/shipping/workspace` | 保存工作区 |
| `syncShippingReceipts` | `POST /kanban/shipping/workspace/sync-receipts` | 从飞书视图同步来货并保存 |
| `syncShippingSkuPlans` | `POST /kanban/shipping/workspace/sync-sku-plans` | 从飞书视图同步 SKU 渠道计划并保存 |

后端仍保留旧文件解析接口用于兼容其他客户端；当前页面不调用这些接口。旧接口使用原始 `ArrayBuffer`，请求头为：

```http
Content-Type: application/octet-stream
X-Filename: encodeURIComponent(file.name)
```

## 8. 错误处理

所有保存、演算、导入和导出错误通过 Ant Design Vue `message.error` 显示，优先读取：

```text
error.response.data.detail -> error.message -> 前端默认文案
```

删除和清空必须使用确认对话框。页面不提供重置整个工作区的操作。加载和保存过程中分别使用 `loading` 和 `saving` 状态；标题栏显示最近服务端保存时间。
