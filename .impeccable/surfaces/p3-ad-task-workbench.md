## 任务与依据

供广告运营直接打开权限范围内的 SPU 任务包、查看真实证据、逐层保存判断，再预演并提交获准执行的动作；组长处理转交与执行后核对，广告组/活动关闭不再要求组长级账号提交。任务包以 scope、快照日期、站点、店铺、SPU 区分，不是按展示名称合并的建议卡片。

当前局部视觉依据是用户指定的 `E:/Download/P3广告优化交互演示.html`；此前交互依据包括 `E:/Download/P3广告看板IT演示包.zip`。原 HTML 确有未分配任务的条件领取流程，但用户最新指示取消手动领取，优先于原型该行为。实际行为以当前组件和后端契约为准；原型姓名、数量、金额、角色与继承样例不是生产事实。完整操作边界见 [P3广告任务工作台.md](E:/junlee/Kanban/docs/P3广告任务工作台.md)。

保留 Vben 外壳、侧栏与 Ant Design Vue 控件；本次是实际 UI、接口及快照流程接入，不是静态原型。`apps/web-antd/PRODUCT.md` 是啤酒服历史上下文，不能推导 P3 规则。本记录不修改该文件、全局 DESIGN.md 或既有 [广告建议局部记录](ad-cvr-optimization.md)。

## 页面构成

- 四个视图固定为“今日任务 / 全部任务 / 执行中心 / 执行设置”。按用户要求移除“规则与口径”视图及“历史版本”入口、抽屉；不删除后台历史数据和执行保护。标题下显示快照日期、数据窗口和完整性；不掩盖旧快照或部分完成状态。
- 今日任务首屏依次为浅蓝任务横幅、五张独立状态 KPI 卡片、左侧 SPU/站点/店铺队列、右侧选中任务健康与判断区。状态卡片可筛选队列；归属、处理状态、优先级、负责人、站点及搜索共同限定范围；归属仅保留“全部归属 / 我的任务”，不再提供“未领取”筛选。
- 健康概览与阶段进度先于诊断表。阶段按 `color → target → search_term → ad_group → campaign` 排列，中文为“颜色 → 投放内容 → 搜索词 → 广告组 → 广告活动”；后续阶段受前序判断门禁约束。
- 行内对象名打开证据抽屉，集中显示指标、诊断依据、执行影响、人工判断及判断历史。深层证据不挤入首屏，但不能用省略文案隐藏限制。
- 固定批量执行栏对齐右侧工作区，随容器宽度更新，不横跨应用侧栏或左侧队列；工作区底部留出避让空间。参数与预演使用独立弹窗。
- 全部任务保留完整分页、范围筛选和转交入口，无领取入口。每日容量默认未配置，不展示或截断队列；仅业务明确配置后限制“我的任务”今日排队。团队负载展示当前筛选下真实任务包计数，共同负责人组合单独归组，不混入原型配额。执行中心承载异步批次与逐项回执、失败重试预演及到期/执行后复查。规则与策略继续由服务端执行，不提供独立规则视图。
- 执行设置显示当前模式及三种模式的提交范围；管理员可设置受限试点运营与 SPU、归档快照验收日期、结论和每日队列显示容量。保存前确认真实执行范围，模式变更使旧预演失效。普通运营只读；设置不是广告修改操作。

## 交互与状态

- “保存判断”和“执行广告修改”是两个动作。采纳、修改、保留、观察、忽略保存独立记录；修改保存实际参数，保留/观察/忽略填写原因；观察提供 3、7、14 天。批量判断不覆盖已有未到期决定。
- 复选框允许先选择待判断项；批量判断优先处理本页所选，未勾选时沿用本页批量操作。已选数与可执行数分开显示，只有可执行且已采纳/修改的动作进入参数预览和提交；可跨阶段、跨页保留选择，单批最多 200 项。刷新详情不因加载状态误清选择。预演展示最终动作、继承去重、上层抑制、阻断原因和对象定位，核对后才能提交。
- SPU 健康卡显示同店铺、站点、统计期及权限范围内的自然 CVR 汇总，并标注覆盖的父 ASIN 数；不同广告组的自然 CVR 不再使整张卡留空。多位负责人按建议来源显示姓名与建议条数，避免把合并任务包误读成单一负责人。
- 证据抽屉直接解释只读原因：旧快照、已经提交或写入、父级继承、上层抑制、任务数据尚未加载。未领取或其他人的编辑租约不再作为前端只读原因；有权限且当前详情加载成功后可直接判断。
- 已移除手动领取、释放与定时续租流程；保存、批量判断及执行提交不再要求先领取。后端保存与批量判断使用事务内 `lock_package` 串行化，保留权限、版本、阶段与影子模式门禁，不等于无并发保护或放开广告写入。“处理中”由已有判断且仍有待判断项决定，不再取决于租约。任务归属与转交继续保留；筛选偏好按用户与 scope 隔离保存。
- 版本归档与查询接口保留，工作台不再提供历史版本入口。对象详情中的判断记录仍保留；中文标签集中于 `task-labels.ts`；撤销事件显示“撤销判断”，无记录显示“尚未判断”，不可混同。
- 成功项不自动重放；超时或结果不明先核对。仅明确失败且没有写入记录的项可重新预演，重试仍需人工确认。新快照缺少对象不等于关闭成功；复查结论不能由前端自动补齐。

## 局部视觉与适配

- 按指定 HTML 恢复局部配色：主蓝 `#2563eb`、正文 `#1c2d48`、次级文字 `#718097`、分隔线 `#e4eaf2`、页面底 `#f3f6fb`，白色工作面。浅蓝横幅、选中队列和主动作延续原型层次；状态色辅助文字，不替代状态说明。不再以另选的灰蓝风格覆盖用户原型。

- 桌面队列宽 272px，1550px 以上为 300px，1180px 以下为 240px，右侧工作区自适应；900px 以下改为单列，KPI 为三列、健康指标为两列。560px 以下标题、操作栏及部分操作组换行。五个阶段保持等分网格；宽表局部横向滚动，不把整页撑宽；证据抽屉最大宽度为 480px 且不超过视窗。
- 2026-09-18 滚动修复：桌面左侧队列在工作区范围内跟随视口停留，避让应用顶部栏；筛选与分页不随队列内容滚走，仅任务列表内部滚动。应用外壳的 `overflow:hidden` 会拦截 CSS sticky，因此用逐帧合并的局部位移，不修改外壳；离开工作区时受容器底边约束。900px 以下或可用高度不足 480px 时恢复普通文档流，列表最高 340px，不在窄屏覆盖诊断内容。相关尺寸变化、事件与观察器随组件生命周期清理。
- 视图使用 `aria-current`，队列与汇总筛选使用 `aria-pressed`，阶段使用步骤状态；选择、搜索及参数控件有可访问名称。键盘焦点有可见描边；装饰进度线不进入朗读，进度另有文字。
- 轻量状态过渡用于导航、队列和汇总；`prefers-reduced-motion` 下关闭这些过渡。上述是已实现语义与样式，不等于全流程无障碍认证。

## 不可弱化的约束

- 按真实实体键及 profile/campaign/ad-group ID 证明关系。颜色与同组投放内容是并列维度，禁止虚构“颜色包含关键词”；颜色关闭仅展开真实商品广告。历史场景计算不是未来收益承诺。
- 零花费不等于低 CVR，样本不足不默认批量关闭；缺失指标保留缺省，不补原型数字。站点原币不可跨币种直接加总。
- 默认剔除 `Funspread-US`；仅请求 `projectTags` 包含“雨靴”时允许参与查询。快照保留其原始数据，不把查询例外固化成删数。
- 默认 P3 影子模式允许判断与预演，但服务端阻断广告提交。至少 3 个不同真实归档快照日期和人工验收结论，由管理员登记后才可开放试点或团队执行；试点负责人默认空，由业务明确配置，不复制原型姓名。广告组/活动关闭遵循同一权限、证据、阶段和预演校验，不额外要求组长级角色。
- 新快照不自动迁移旧判断，旧版本不能提交；预演签名、实体与权限在真实提交时再次检查。视觉可用性不能替代这些服务端门禁。
